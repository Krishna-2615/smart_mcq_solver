# 🧠 Smart MCQ Solver: Hybrid RAG & Ensemble LLM Pipeline

## 📌 Project Overview

The **Smart MCQ Solver** is an advanced machine learning pipeline designed to answer complex domain-specific **Multiple-Choice Questions (MCQs)**, specifically targeting **Physics**.

Instead of relying on a single model, this project uses a **Knowledge-Augmented Ensemble Approach** that combines:

- A custom **Knowledge Graph**
- **Semantic Vector Retrieval**
- A **Hybrid RAG (Retrieval-Augmented Generation) system**
- Three different neural architectures
- Probability-based ensemble optimization

The goal is to maximize prediction accuracy by combining complementary retrieval and modeling techniques.

---

## 🚀 Key Techniques & Innovations

### 📚 1. Custom Knowledge Base Construction

The pipeline automatically scrapes targeted **Physics concepts from Wikipedia** and constructs a localized knowledge base.

The extracted information includes:

- Core concepts
- Important terms
- Definitions
- Conceptual relationships

This knowledge base is then used by the retrieval and model inference stages.

---

### 🔗 2. Hybrid Graph-RAG System

The project combines **graph-based retrieval** with **semantic vector retrieval**.

#### Graph Retrieval

**KuzuDB** is used to construct a knowledge graph representing conceptual relationships.

Example relationship:

```text
Topic → HAS_TERM → Term
```

This allows the system to retrieve highly relevant information when an exact conceptual relationship exists.

#### Semantic Fallback

When graph retrieval does not provide sufficient context, the system falls back to semantic search using:

- **FAISS** — Vector similarity search
- **BAAI/bge-small-en-v1.5** — Sentence embeddings

This enables the system to retrieve broader contextual information related to the question.

### Retrieval Flow

```text
MCQ
 │
 ▼
Knowledge Graph Retrieval
 │
 ├── Relevant Context Found
 │        │
 │        ▼
 │     Use Context
 │
 └── No / Weak Match
          │
          ▼
     FAISS Semantic Search
          │
          ▼
     Retrieved Context
```

---

## 🤖 3. Three-Model Blended Ensemble

The pipeline combines predictions from three different models.

### 1. Cross-Encoder (CE)

A fine-tuned:

```text
microsoft/deberta-v3-small
```

model is used as a cross-encoder.

The model receives:

```text
Question + Context + Option
```

and learns to score each option.

Training uses:

```text
Binary Cross-Entropy (BCE) Loss
```

The cross-encoder is particularly useful for evaluating the relationship between the question, retrieved context, and individual answer options.

---

### 2. Scratch Transformer

A custom Transformer encoder is trained **from scratch**.

Unlike pretrained Transformer models, this model uses:

- Randomly initialized parameters
- A custom vocabulary
- Training data specific to the target corpus

This allows the model to learn domain-specific patterns directly from the available Physics corpus.

---

### 3. Instruction-Tuned LLM

The pipeline also uses:

```text
Qwen/Qwen2.5-3B-Instruct
```

The model is:

- Quantized to **4-bit**
- Loaded using **NF4 quantization**
- Fine-tuned using **QLoRA**
- Trained using **PEFT**
- Optimized using TRL's **SFTTrainer**

This provides the pipeline with the reasoning and language understanding capabilities of an instruction-tuned LLM while reducing GPU memory requirements.

---

## ⚡ 4. Optimized Ensemble Inference

Rather than selecting predictions from a single model, the pipeline combines the probability distributions generated by all three models.

The ensemble can be represented as:

```text
P_final =
    w_scratch × P_scratch
  + w_ce      × P_ce
  + w_llm     × P_llm
```

where:

```text
w_scratch + w_ce + w_llm = 1
```

A dynamic **grid search** is performed to find the optimal combination of model weights.

The optimized weights are selected based on validation performance using **MAP@3**.

# 📈 Evaluation & Metrics

The primary evaluation metric used by this project is:

## MAP@3 — Mean Average Precision @ 3

MAP@3 evaluates how effectively the system ranks the correct answer within the **top three predicted options** for each MCQ.

The ensemble optimization process performs a grid search over the three model weights.

The constraint is:

```text
w_scratch + w_ce + w_llm = 1.0
```

Using a grid-search step size of:

```text
0.1
```

the system evaluates different combinations of model weights on the validation set.

Example:

```text
w_scratch = 0.2
w_ce      = 0.5
w_llm     = 0.3

0.2 + 0.5 + 0.3 = 1.0
```

The combination producing the highest validation **MAP@3** is selected for the final ensemble.

# 💡 Why This Approach?

A single model may struggle with different types of MCQs.

This pipeline combines different strengths:

| Component | Primary Role |
|---|---|
| **Kuzu Knowledge Graph** | Exact conceptual relationships |
| **FAISS** | Semantic/contextual retrieval |
| **DeBERTa Cross-Encoder** | Question-context-option scoring |
| **Scratch Transformer** | Domain-specific representation learning |
| **Qwen2.5-3B** | Instruction following and language reasoning |
| **Ensemble Optimization** | Combines complementary predictions |
| **MAP@3** | Measures top-3 ranking quality |

The resulting architecture is a combination of **RAG, Knowledge Graphs, Information Retrieval, Transformer models, LLM fine-tuning, and ensemble learning**.
